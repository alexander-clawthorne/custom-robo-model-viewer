Custom Robo 3DS

Rebuild Custom Robo (GameCube, USA, GXCE01) to run on a Nintendo 3DS: arena battles and the story campaign. Everything is converted from your own disc on your own PC; no game data lives in the repo.

Repo: alexander-clawthorne/custom-robo-3ds (private) Engine: HAL sysdolphin (same as Melee) Test: Citra 60 FPS, 3DS via FileZilla

Phase 3 · World data
12Donebg_data.BINArena collision decoded (tools/collision.py): 414 blocks and 3165 faces across the 40 arenas. Each block is a bounding sphere plus convex faces that carry their own plane; block 0 is the arena shell (four inward walls and a floor, no ceiling). Quads everywhere except arena 7, which uses triangles — nothing in the header says which, so the record stride is taken from the gap to the next block. The game’s own sweep (0x8005d08c) and face test (0x8005e270) confirmed the block flags and that the entry’s large trailing section is runtime scratch, not data. Cooked to romfs/collide and drawn on the 3DS as its own viewer category.
13In progress*_effect.BINWeapon and hit effects decoded (tools/effects.py). Each SFD entry of attack/gun/bomb/pod_effect.BIN is a container of its own holding two standard HSD archives; efc_common.dbn is that container without the SFD. 350 effect models are cooked and render on the 3DS. Their animation is stock HSD keyframes, and all 13,142 tracks now decode: joint transforms, material colour and alpha, texture UV and 4- or 8-frame flipbooks, plus a particle-trigger track whose keys carry only a frame. Correction: this step was planned around “HSD particles in leg_effect.BIN”; there are none. No joint in any effect file sets JOBJ_PTCL, and the particle track’s AObj has no flags and a null object id, so nothing in the files says what is spawned — only when. What each trigger fires must come from the DOL, keyed by the effect index. Still to do: play the animation on the 3DS, and find the spawn table in the code.

How the joints and textures came out right

Nothing was guessed into place: each fix was checked against code that already runs these formats correctly.

Joints

Custom Robo is built on HAL's sysdolphin engine, the same one as Melee. The Melee decompilation has turned that engine back into readable C, so the joint layout (position, rotation, scale, children) and the order rotations apply in come straight from it.

The one hard bug was the arms and legs. They are inverse-kinematics chains, and reading the engine's own code (resolveIKJoint1, resolveIKJoint2 and the effector case in jobj.c) showed the rule: a chain is only solved when its end joint has a target, and otherwise the end joint is placed one bone length along its parent. Using that rule put every limb where it belongs.

Animation used the same approach one level up: the motion code in the game itself was decompiled with Ghidra (REA cannot open PowerPC), and its two-pass solve was rebuilt step by step.

melee: jobj.c · doldecomp/melee · HSDLib (HSD file layouts)

Textures

GameCube textures are compressed and stored in small tiles. The decoder follows the formats as Dolphin (the GameCube emulator) implements them, and each result was checked with a PC render before going near the 3DS.

The 3DS stores textures in its own tiled order. The first 3DS build had scrambled colours because the image was flipped twice. The fix was to encode a test image with devkitPro's own converter, tex3ds, and change the cooker until its output matched byte for byte.

Dolphin: TextureDecoder_Common.cpp · devkitPro/tex3ds · devkitPro/citro3d

How it was checked

Two independent checks every time. A software renderer on the PC draws each model straight from the decoded data, so decoding mistakes show up without the 3DS involved. Then an automated Citra run steps through every category and screenshots it, which catches anything that only goes wrong on the 3DS GPU.

Code: tools/hsd.py · tools/gxtex.py · tools/cook.py (private repo)

Watch-outs

Gameplay has no head start

The MKW port borrowed Kinoko's finished physics. Nothing like that exists for Custom Robo, so movement, weapons, damage and AI are rebuilt from the game's PowerPC code and observation. This is the largest phase by far.

Bombs might be sideways

Guns now stand upright; bombs keep their mount rotation and lie horizontal. Unconfirmed which you expect.

Feet in the bind pose

Resolved: feet point forward once a motion plays. They only lie sideways in the bind pose, which X / SELECT can still step to.

Some arenas are only sky

Arena entries 1, 8, 15, 38 and 39 are space backdrops without a floor; one entry is a ? model.

Size on the SD card

The viewer is now 405 MB because vertices are stored unindexed; the story maps alone added about 150 MB. Indexing (step 27) should cut that a lot, and may need doing sooner than planned.

Citra input

Your Citra profile is controller-only, so emulator checks use the AUTOTEST build and background screenshots instead of key presses.
